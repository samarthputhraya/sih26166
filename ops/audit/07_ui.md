## What was built — and what a judge now sees

- **Light paper ground** (`#F7F7F4`) instead of stock dark. A projector in a lit classroom cannot
  project black; ink on paper is what the judges have read all their lives. Every colour on the
  page is a palette hex; contrast on the ground: ink 16.6:1, muted 6.2:1, faint 5.4:1, caution
  4.9:1 (used for a word and a 4px bar only, never a sentence), ok 6.1:1, fail 7.0:1.
- **One config file, one CSS block.** `.streamlit/config.toml` (theme, `gatherUsageStats=false`,
  `toolbarMode="minimal"`, `fileWatcherType="none"`) and the `SKIN` string in the app. Every
  config key was checked against the installed streamlit 1.62.0 and the check is a test, so an
  unknown key or a font URL fails `pytest` before Gate 4 rather than during it. System font stacks
  only (Consolas / Segoe UI); no `http`, `url(` or `@import` anywhere in the skin.
- **The web-app tells are gone.** No Deploy button, no rainbow bar, no rounded pastel
  `st.success/warning/info/error` in the main column, no `st.metric` trio, no `st.title` hero, no
  emoji, no shadow, no radius, no "?" tooltips. Sections are numbered `01 RESULT` … `06 WHAT
  THESE NUMBERS DO AND DO NOT PROVE` over hairline rules; the sidebar panels are `SELECT PAIR /
  ALIGN / DISPLAY` (unnumbered, so there is one numbering scheme on screen).
- **State is never colour alone.** Every verdict is a WORD first (`ALIGNED` / `FALLBACK USED` /
  `NO TRANSFORM` / `CONTRADICTED` / `ERROR`) with a 4px bar second. PASS/FAIL are words with the
  Gate 2 threshold beside them, written as Canonical Facts §11 writes it (`> 0.60`, `>= 0.80`,
  `< 1.0`), under a one-line note that Gate 2 is judged on the synthetic sweep, not on this pair.
  The reliability map draws three *kinds* of mark: verified = tint + solid border + "V"; weak =
  tint + 45-degree hatch + dashed border + "W"; no evidence = **no tint**, faded toward paper,
  dotted border, "-". The legend swatches are the overlay's own tint maths over the plate colour
  and use the same 8px hatch period, and an ASCII cell map (`core.reliability.ascii_map`) sits
  beside the picture so it survives a photograph of the screen (`final_p01_trust.png`,
  `p04_trust.png`: 60 faded cells, 4 hatched — absence renders as absence).
- **The primary readout cannot render a bare pixel number.** `readout_for()` is a pure function
  of the result dict with four forms, every one of which names the reference grid: value + metres
  (reference label carries a scale); value + `METRES NOT AVAILABLE` and the reason (pair_01: no
  label carries a map scale); greyed value + "MATCHER TRANSFORM NOT USED" + the metres it would
  have implied (pair_04: 4684.9 px = 43,897 m — the story is *that the system caught it*); greyed
  value + "NO TRANSFORM". The number carries the qualifier "held-out fit residual, not an
  accuracy" at body size beside it, not in a 12px grey label. In the metrics table the same
  residual is drawn void with "matcher transform, not used" whenever the fallback was used, so a
  photograph of the table alone never carries a bare 4,685 px "residual". A value that rounds to
  its own threshold is drawn to six places, so the digits on screen can never contradict the
  PASS/FAIL word beside them.
- **An identification plate and a state rail** replace the marketing caption: `CPU ONLY` /
  `OFFLINE` / `REFERENCE GRID {gsd} m/px` or `NOT DECLARED` / `CACHED RESULT commit {c}` or
  `RESULT LIVE RUN`, then `PAIR / TIER / SENSORS / STATE / RESULT SOURCE / ELAPSED`. The plate is
  filled the moment the result is known (so the title never blanks during a live run); the rail
  is an `st.empty()` filled at the very end of the script, so STATE can never read `READY` above a
  live result. Tier and sensors come from Rohan's catalogue **for the pair the result came
  from**, not for whatever the sidebar currently points at, and every pair-changing input (the
  selector, the source radio, the uploaders) resets the result — a stale result can never sit
  under a new pair's name.
- **Projector mode** (sidebar checkbox) re-injects the same block at 20px instead of 17px.
  Streamlit is rem-based, so every widget and label scales and the imagery does not; the ASCII
  map scales too (`1.06rem`, not a fixed px).
- **Vertical space, measured at 1366x768:** the Align button sits at y=580 on the demo pair (it
  was at y=765, below the fold); the first image at y=379 with its caption at y=717 (was 443 with
  captions off-screen); swipe and trust map are `[3, 2]` column layouts with their explanation
  beside the picture, so each fits one screen.
- **Performance:** the reliability overlay is drawn once per result into `session_state`
  (`overlay_rel`, cleared by `reset_results`), not on every seam-slider drag.
- **Print fallback:** `@media print` hides the sidebar and keeps bars and tints, so Ctrl+P → PDF
  is a handout if the projector dies.
- **Every interpolated string** (catalogue notes, `declared['why']`, upload filenames, pair
  labels, error text, the ASCII map, the rule string) goes through `html.escape` before it
  reaches an f-string. The pipeline's own `->` in `declared['why']` is drawn as an arrow; the
  sentence is otherwise verbatim.
- **Wording that was a number without a measurement is gone:** "about 15 s" now reads the
  sidecar's own seconds for the selected pair; "CPU time" (it was wall-clock `perf_counter`) is
  now "elapsed" everywhere; "precomputed on this laptop" (the sidecar records no machine) is now
  "precomputed {when}, commit {c}".

### Deviations from `07_UI_SPEC.md`, each with its reason

1. **Config Block B is enabled, not commented.** The spec left it commented because its author
   could not import streamlit. I ran the key check against the real venv: every key exists in
   1.62.0, the app boots clean, and `test_config_toml_uses_only_keys_this_streamlit_knows` re-runs
   the check on every `pytest`. Font *stacks* are in `theme.font/headingFont/codeFont` (accepted
   since 1.45; the refuter traced `theme_util._parse_font_config` and confirmed no exception path
   and no font source for these values); the CSS repeats them on our own classes.
2. **Ratios print to four places, not three.** `inlier_ratio` 0.9996 to three places is `1.000`,
   which a judge would read as "every match was an inlier". Four places is also how the deck prints
   every Gate-2 figure (0.9774, 1.0000, 0.4006), so the screen matches the slide digit for digit.
3. **Four readout forms, not two.** The spec's two-form rule would grey out the flagship number
   (pair_01 carries no map scale) and, as built to the letter, printed the fallback residual with
   no grid. Every form now names the grid; only the form with a reference scale prints metres.
4. **Verified tint alpha 0.25 (spec 0.30); glyph scale `cell/95` (spec `cell/60`).** At 0.30
   with 63 green cells the crater floor went black-green and the glyphs were posters over the
   terrain. Judged on `overlay_pair_01.png`; one constant each if rehearsal step (b) disagrees.
5. **The rail omits `CPU - OFFLINE`** (the plate strip above already says it) and reads `ELAPSED`,
   not `CPU TIME` (it is wall-clock time).
6. **Swipe and trust map are `[3, 2]` columns** so each fits a 768px projector screen with its
   explanation beside it instead of above it.
7. **`help=` tooltips removed**; the "?" icon is a Streamlit tell and the caption carries the text.
8. **Footer expander titled "The four definitions"** so it does not repeat the `06` label. The
   four bullets are verbatim.
9. **The selector opens on `pair_01`**, not on `pair_00_dryrun` (alphabetical first, uncatalogued).
10. **Border thickness scales with the cell** (1–3 px) so pair_03's 12px cells are not eaten.
11. **The sidebar has no tier/sensor rows** (the rail shows them, and they pushed Align below the
    fold); the same-instrument sentence stays exactly where and as it was.
12. **Sidebar panels are unnumbered** (`SELECT PAIR / ALIGN / DISPLAY`), so "look at 02" has one
    meaning on screen.
13. **The success word is `ALIGNED`, not `DECLARED`**, so a stranger reads what happened; the
    sentence beside it still says the method was declared and why.
14. **The plate is filled early, the rail late.** The spec reserved only the rail; the plate's
    grid tag needs the result too, but filling it last blanked the title for 15–20 s during a live
    run. It is filled the moment the result is known.
15. **The module docstring's gate days are corrected** to Gate 3 = Day 8 (6 Sep), Gate 4 = Day 9
    (7 Sep), per `00_CANONICAL_FACTS.md` §11. The old file said Day 10 / Day 11.

## Findings — things the rebuild exposed that are NOT in the UI file

### HIGH — the two Tier D demo pairs are not in the catalogue, so the UI must call them "tier unknown"
- **Evidence:** `data/pairs_catalogue.csv` has `pair_id` values `pair_01, tier_bplus_01,
  tier_a_01, tier_d_01`. The directories are `data/pairs/pair_03_tierD` and
  `data/pairs/pair_04_tierD_native`; `catalogue_row("pair_04_tierD_native")` returns `{}`. The
  rail on the Tier D demo therefore reads `TIER unknown / SENSORS unknown` and the sidebar prints
  *"pair_04_tierD_native is not in pairs_catalogue.csv, so its tier is unknown. A number without
  its tier is not evidence."* (`final_p04_top.png`). The refuter confirmed every line and noted
  `ops/PLAN_TO_9_SEP.md:159` already lists "same Tier D pair under two pair_ids — normalise".
- **Why it matters:** the deck's slide 2 and slide 4 call this pair Tier D, optical vs elevation,
  and `QA_ANSWERS.md` §3 makes it the answer to "where is multi-modal?". The UI — by design,
  Invariant 2 — refuses to say so because the catalogue does not. A judge who reads both sees the
  demo contradict the slide on the single pair that carries the 25% novelty claim.
- **Fix:** Rohan appends two rows to `pairs_catalogue.csv` with `pair_id` equal to the directory
  names, `tier=D`, **`source_instrument=Kaguya_TC`** (the existing `tier_d_01` row leaves it blank,
  which would render `? vs LOLA_LDEM`), `ref_instrument=LOLA_LDEM`, GSDs from each pair's
  `PROVENANCE.md` (9.3698731836556 / 60.0 for pair_03; 9.3698731836556 / 9.3698731836556 for
  pair_04), `notes` saying pair_04 is the same crop re-rendered on the Kaguya grid. Restart the
  app afterwards (`catalogue_row` is `st.cache_data`-cached). `data/` is Rohan's folder.
- **Risk of fixing:** none to code. Test: AppTest selecting `pair_04_tierD_native` and asserting
  the rail's TIER cell reads `D`.

### HIGH — the flagship pair's headline number has no metres, and cannot have one from the label
- **Evidence:** `demo_cache/results/pair_01.pkl` → `gsd_mpp: None`, `meta_reference.gsd_mpp:
  None`, `scale_note: "gsd_mpp unknown for source and reference; images NOT resampled"`. The
  catalogue and `data/pairs/pair_01/PROVENANCE.md` both record 0.22977 m/px for the OHRC
  product, but `core.io_loader` does not read it from the bare `.tif` and the pipeline never
  consults the catalogue. The readout therefore says `METRES NOT AVAILABLE` on the pair every
  demo starts with (`final_p01_metrics.png`).
- **Why it matters:** CLAUDE.md Invariant 2: *"sub-pixel — always name the pixel grid and give
  the metres equivalent."* The UI names the grid; it cannot give the metres. The first question a
  judge asks about `0.0376 px` is "so how many centimetres?", and the honest answer today is "the
  label does not say". `ops/QA_ANSWERS.md` §2 quotes 0.038 px for pair_01 with no metres either.
- **Fix (not for the UI):** either (a) `core.pipeline` accepts a per-pair GSD from the catalogue
  when the label has none (it is I/O metadata, not the matcher, but it lives in a frozen folder and
  must be argued as such), and the cache is re-run; or (b) the demo script and Q&A say, in words:
  *"0.038 px on the OHRC reference grid; the catalogue lists OHRC at 0.23 m/px, so under a
  centimetre — the file itself carries no scale so the tool does not print metres."* (b) needs no
  code and no gate. The UI will take the metres form automatically the moment
  `meta_reference.gsd_mpp` is non-null.
- **Risk of fixing:** (a) changes the *metres* line only; `residual_px` is in pixels and cannot
  move. Test: `core/test_io_loader.py` asserts the OHRC pair yields 0.22977.

### MEDIUM — the demo cache was written from an uncommitted tree and its sidecar names a commit that lacks the code
- **Evidence:** every `demo_cache/results/*.json` carries `git_commit: fce6d05`, `computed_at

- **Risk of fixing:** none to numbers (the cache is the same output). Test: the sidecar's commit
